# 效果展示页设计

## 目标

在现有在线微信编辑器项目中新增一个独立的“效果展示页”，用于向别人直接展示最终排版成品长什么样。

这个页面的任务不是解释规则、不是教学，也不是提供编辑能力，而是让访问者一打开就能快速理解：这个工具最终能产出什么样的公众号成品内容。

## 用户已确认的方向

本次需求已经明确以下约束：

- 展示页从主编辑器工具栏进入
- 工具栏新增一个 `效果展示` 按钮
- 点击后单独打开一个新页面，不打断当前编辑流程
- 展示页不是交互演示工具，不让访问者自行输入内容
- 展示页采用固定示例内容，打开即见结果
- 页面重心是“这个成品”本身，不是平均分配的教程式前后对比
- 左侧只保留轻量说明，右侧完整展示最终排版效果
- 示例内容使用一篇公众号风格案例文，重点展示标题、蓝字、笔刷、红框等真实输出样式

## 页面定位

这是一个结果展示页，不是编辑器附属预览页。

它应当更接近“案例成品展示”而不是“后台工具界面”，让访问者把注意力放在文章成品的阅读感和排版完成度上。

换句话说，这一页回答的问题只有一个：

> 用这个工具整理后，最后能做成什么样？

## 信息架构

展示页建议作为一个新的独立文件，例如：

```text
在线微信编辑器/
├─ Markdown编辑器_蓝色主题 - Copy.html
├─ rules.html
├─ demo.html
├─ styles/
│  └─ editor.css
└─ scripts/
   └─ editor.js
```

入口关系如下：

- 主编辑器工具栏新增 `效果展示`
- 点击后打开 `demo.html`
- `demo.html` 与主编辑器、规则页共用同一套本地 CSS 和 JS
- `demo.html` 可以被单独双击打开，便于单独发给别人查看

## 页面结构

### 1. 顶部短标题区

顶部只保留非常克制的说明，不做营销型 hero，也不加入复杂导航。

建议内容：

- 标题：`排版效果展示`
- 辅助文案：`适合公众号发布的最终成品示例`

这一块的作用只是建立语境，不应该抢正文的注意力。

### 2. 左侧轻提示区

左侧不是主角，只承担“交代来源”的作用。

建议只放三类信息：

- 原始素材：说明这类内容通常是口语化、零散、场景化的素材
- 整理目标：说明整理后会变成适合公众号发布的成品内容
- 展示重点：列出这页主要展示的要点，例如 `标题层级 / 重点词 / 笔刷 / 红框`

左侧不放完整原文，不放长篇说明，也不写规则教学。

### 3. 成品主展示区

右侧是页面绝对主角，必须完整展示一篇真实成品。

这一块直接使用固定案例内容，并保留项目当前已经存在的真实输出样式：

- 左蓝杠副标题
- 蓝色重点词
- 笔刷高亮
- 红框总结段
- 正文行距和段落节奏

右侧不应表现为“编辑器预览弹层截图”，而应表现为一篇已经成型的文章样稿。

### 4. 底部收尾区

底部只需非常轻的收束，例如：

- `这是最终可交付的排版效果示例。`

如果需要，也可以在这里加入轻量的返回入口，但不应增加过多动作按钮。

## 布局策略

整体采用“左轻右重”的双栏结构。

### 桌面端

- 左侧为窄栏，承载说明信息
- 右侧为宽栏，承载完整成品内容
- 视觉重心明确偏向右侧
- 第一屏就能看到右侧成品正文开头，而不是只看到说明卡片

### 移动端

- 自动切换为上下布局
- 先显示顶部短标题和左侧说明信息
- 再完整显示成品内容
- 保证手机上阅读顺序自然，不出现左右过窄导致的拥挤感

## 内容组织

### 左侧内容原则

左侧只负责说明“内容从哪里来”，不负责取代正文。

推荐放法：

- `原始素材`：简短描述素材的原始状态
- `整理目标`：一句话说明会被整理为公众号发布成品
- `展示重点`：点出标题、重点词、节奏高亮、结论红框

左侧禁止：

- 放整篇原文
- 长篇规则说明
- 多步骤流程解释
- 大段文字挤占主视线

### 右侧内容原则

右侧直接进入成品，不先做过程解释。

推荐展示方式：

- 第一屏完整展示一个强场景段落
- 场景一必须完整显示到红框总结段
- 继续向下滚动时展示第二个场景，形成稳定的连续成品感

当前已确认可作为示例成品的内容包括：

- `场景一：掐人怎么办 —— 用“搞怪”打破僵局（情绪急救法）`
- `场景二：弹广告牌 —— 用“游戏”转化行为`

这样访问者在首屏就能看到标题、重点词、笔刷与红框；继续下滑时又能确认这不是单段样式，而是整篇都能成立的输出效果。

## 视觉方向

### 总体气质

页面应当偏“内容作品展示”，而不是 SaaS 营销页，也不是后台工具截图页。

视觉关键词：

- 克制
- 安静
- 成品感
- 阅读感
- 不打扰正文

### 背景与层级

建议整体背景保持浅灰白或浅灰蓝，降低存在感。

真正有分量的区域是右侧成品展示区，让它像一张被托起来的文章页面，而不是平铺在工具背景上。

### 成品区宽度

右侧成品区应当按公众号阅读宽度控制，不要过宽。

这样即使在桌面端浏览，也会自然让人联想到移动端公众号阅读体验，而不是一块普通网页正文区域。

### 左侧弱化

左侧说明区颜色更淡、字号更小、信息更少。

它存在，但不与成品正文争夺视觉中心。

### 不采用的方向

为了保持页面纯度，明确不采用以下做法：

- 不做复杂 hero 横幅
- 不做营销页式夸张卖点文案
- 不做轮播示例
- 不做多篇文章切换器
- 不把页面做成当前预览弹窗的放大版
- 不加过多按钮或功能入口

## 示例内容使用原则

本页右侧展示内容应直接使用真实成品案例，而不是临时拼凑的假排版样稿。

这有两个好处：

- 访问者看到的就是实际交付效果
- 页面本身同时成为对外展示样稿

当前建议直接使用用户已提供的成品案例，保留其现有标题、蓝字、笔刷、红框与正文节奏。

## 交互原则

这是展示页，不是操作页，因此交互应非常轻。

建议只保留：

- 从主编辑器打开展示页
- 展示页自身的自然滚动阅读
- 如有需要，可增加一个轻量的返回编辑器入口

明确不需要：

- 用户输入区
- 现场生成按钮
- 切换模板功能
- 展示页内的复杂说明面板

## 实现边界

本次只新增一个固定内容的效果展示页，不扩展到更复杂的案例系统。

明确不包含：

- 多篇展示内容切换
- 自动读取编辑器当前内容生成 demo
- 在线分享链接系统
- 展示页内编辑能力
- 对比动画或复杂交互

## 测试与验证

完成实现后，需要重点验证以下项目：

1. 主编辑器工具栏出现 `效果展示` 按钮
2. 点击按钮可打开 `demo.html`
3. `demo.html` 双击直接打开时也能正常展示
4. 第一屏能直接看到右侧成品正文开头
5. 左侧信息区不会喧宾夺主
6. 右侧成品样式与当前真实输出保持一致
7. 红框、蓝字、笔刷等展示稳定
8. 手机宽度下页面会切为上下布局且仍然可读

## 结论

这个效果展示页的本质，不是解释工具怎么工作，而是把最终成品安静、直接、有说服力地摆在别人面前。

页面结构应当遵循一句话：

> 左边负责交代来源，右边负责证明结果。

只要访问者一打开就能在第一屏看到真实成品的完成度，这一页就达成目标了。
