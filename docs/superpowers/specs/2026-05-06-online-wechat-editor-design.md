# 在线微信编辑器改造设计

## 目标

在现有 `Markdown编辑器_蓝色主题 - Copy.html` 基础上改造成一个本地离线可用的公众号排版工作台。

第一版重点不是自动生成内容，而是搭好一个稳定、顺手、可长期使用的工作台：

- 主页面聚焦长文 Markdown 编辑
- 规则和快速样式说明独立到单独页面，方便打开查看和复制
- 预览改为全屏弹层，减少常驻预览对编辑空间的挤占
- 所有 HTML、JS、CSS 和 Markdown 解析依赖都放在本地，避免外网依赖

## 当前项目上下文

当前目录中已有两个文件：

- `Markdown编辑器_蓝色主题 - Copy.html`
- `规则.txt`

现有 HTML 已具备：

- Markdown 编辑区
- 实时预览区
- 打开文件、保存文件、复制 HTML、清空等按钮
- 使用外链 `marked` 脚本进行 Markdown 解析

现有问题：

- 页面仍是通用蓝色主题编辑器，不是面向公众号工作流的界面
- 还没有独立规则页入口，无法直接打开和复制排版规则
- 预览常驻占位，编辑空间有限
- 依赖 CDN，不满足完全离线要求
- HTML 内联 CSS/JS 体量较大，后续维护不便

## 用户确认的范围

本次改造已确认以下约束：

- 接到现有文件，不新起项目
- 主界面保持编辑器优先，不再放置页内左侧规则栏
- 工具栏提供规则按钮，打开单独的 `rules.html`
- `rules.html` 承载“规则 + 快速样式说明”
- 预览采用全屏弹层方式打开
- 页面必须完全离线可用，本地保存所有 JS、CSS 和依赖文件
- 红色边框模块需要顶格、整段、铺满整行，视觉要接近用户给的参考图

## 第一版定位

这是一个本地离线的公众号排版工作台，不是自动改写工具。

第一版先解决以下问题：

- 如何让长文编辑空间足够大
- 如何让规则可见、可复制、可传给别人，同时不挤占主编辑空间
- 如何快速查看最终排版效果
- 如何在无网络环境下正常打开和使用

明确不包含：

- AI 自动改写
- 按规则自动生成排版成品
- 多套规则模板切换
- 账号、云同步、数据库
- 富文本工具栏
- 移动端优先编辑体验

## 信息架构

### 顶部工具栏

工具栏保留，但重排为与当前工作流更匹配的操作：

1. `规则`
2. `打开文件`
3. `保存 Markdown`
4. `复制 HTML`
5. `预览`
6. `清空`（保留，可放在最后）

设计原则：

- 保持应用栏风格，厚度比当前略收敛
- 强调高频动作，不加入复杂菜单
- 操作完成后用轻量 toast 提示结果

### 规则页

规则内容不再常驻主页面，而是由工具栏 `规则` 按钮打开单独的 `rules.html`。

`rules.html` 由两部分组成：

1. 快速样式说明
2. 完整规则正文

快速样式说明用于一眼说明当前支持的写法，内容简短明确，例如：

- `## 标题` 会转副标题样式
- 蓝字用于核心概念
- 棕字用于问题和痛点词
- 笔刷只用于短词短短语
- 红框用于一整段本质段或落点段

完整规则正文默认读取 `规则.txt` 内容并显示在只读区域，支持滚动和一键复制。

规则页要求：

- 作为独立页面打开后可以专注查看规则
- 规则文本可选中复制
- 支持独立滚动
- 不允许误编辑规则内容

### 主编辑页

主页面保留为主工作区，用于粘贴原始素材和手工整理内容。

要求：

- 页面主体尽量把空间留给编辑区
- 大面积留白，适合长文编辑
- 支持打开本地 `.md`、`.markdown`、`.txt`
- 支持保存当前内容为 `.md`
- 保持纯文本输入体验，不增加复杂工具条
- 占位提示改成面向公众号工作流的文案

### 全屏预览层

点击 `预览` 后弹出全屏遮罩层。

预览层包含：

- 半透明深色背景遮罩
- 居中的白色内容区域
- 右上角关闭按钮
- 点击遮罩空白处关闭

预览内容取自当前编辑区最新内容并实时渲染，不要求用户先保存。

预览区目标是更接近公众号阅读效果，因此会控制：

- 内容宽度
- 段间距
- 标题、引用、红框、列表等视觉呈现

## 本地文件组织

保留原 HTML 作为入口，但将样式和脚本拆到本地文件中。

建议结构：

```text
在线微信编辑器/
├─ Markdown编辑器_蓝色主题 - Copy.html
├─ rules.html
├─ 规则.txt
├─ styles/
│  └─ editor.css
├─ scripts/
│  ├─ editor.js
│  └─ marked.min.js
└─ docs/
   └─ superpowers/
      └─ specs/
         └─ 2026-05-06-online-wechat-editor-design.md
```

说明：

- `marked.min.js` 本地化，替代外链 CDN
- `editor.css` 管主编辑页、规则页和预览样式
- `editor.js` 管编辑器逻辑、规则页加载、文件操作、预览弹层、复制等行为
- `规则.txt` 继续保留为规则源文件，页面运行时读取

## 功能设计

### 1. 规则加载

`rules.html` 启动后优先尝试读取同目录下的 `规则.txt` 并填充到规则区域。

考虑到本地文件在浏览器 `file://` 协议下读取可能受限制，第一版设计采用双保险策略：

- 页面内置一份默认规则文本作为回退内容
- 若浏览器允许读取本地 `规则.txt`，则以文件内容覆盖默认内容

这样可以保证：

- 双击 `rules.html` 直接打开也能正常使用
- 即使本地读取受限，规则页也不会空白

### 2. 复制规则

点击 `复制规则` 后，将规则页中的规则全文复制到剪贴板。

交互要求：

- 优先使用现代剪贴板 API
- 不可用时降级为选区复制方案
- 成功或失败均给出 toast 提示

### 3. 打开规则页

点击工具栏 `规则` 按钮后，在新窗口或新标签中打开本地 `rules.html`。

交互要求：

- 默认不打断当前编辑状态
- 浏览器若拦截打开行为，给出 toast 提示
- `rules.html` 本身可单独双击打开，便于脱离主页面使用

### 4. 打开文件

保留现有文件选择器能力，支持导入：

- `.md`
- `.markdown`
- `.txt`

导入后将内容写入编辑区，并刷新预览缓存。

### 5. 保存 Markdown

将当前编辑内容保存为本地 `.md` 文件。

命名策略可沿用现有日期命名方式，但文案更明确，例如：

- `公众号排版稿_2026-05-06.md`

### 6. 复制 HTML

将当前编辑内容渲染后的 HTML 复制到剪贴板，供粘贴到微信公众号编辑器或其他平台。

复制对象应是预览用的完整 HTML 片段，而不是原始 Markdown。

### 7. 预览弹层

点击 `预览` 打开全屏预览层。

打开时：

- 从当前编辑区读取内容
- 使用本地 `marked` 渲染
- 将结果注入预览容器

关闭方式：

- 点击右上角关闭按钮
- 点击遮罩空白区域
- 可选支持 `Esc` 键关闭

### 8. 清空

保留清空功能，但为避免误操作，建议：

- 第一版可直接清空
- 如果实现成本低，可增加一次确认弹窗

推荐第一版增加轻确认，避免误删长文素材。

## 视觉设计

整体风格定位为“内容工作台”，不是炫技型编辑器。

### 基调

- 干净
- 稳定
- 低干扰
- 长时间阅读和编辑不累

### 页面背景

- 放弃现有大面积蓝色渐变背景
- 改用浅灰白或浅灰蓝底色
- 减少模板感，提升工具感

### 页面结构

- 主编辑页以单页编辑器为主，减少非编辑信息干扰
- 规则页单独成页，但视觉语言与主编辑页保持一致
- 两个页面都用清晰但不厚重的边界和卡片感

### 工具栏

- 比当前更薄、更克制
- 仍然保留蓝色作为品牌色/操作色
- Hover 反馈轻微，不做大幅位移动画

### 编辑区

- 继续使用适合长文录入的字体和行高
- 代码感字体可保留给纯 Markdown 输入区
- 内边距适当放大，提高阅读和编辑舒适度

### 预览层

- 深色遮罩突出主体
- 中央白色内容区宽度适中
- 预览内部样式以公众号阅读效果为参考

### 红框模块修正

红色边框模块按用户最新要求处理：

- 顶格
- 整段承载
- 铺满整行
- 不在左右额外缩进
- 内部文字自然换行

这意味着预览区里所有红框样式都要重新收紧，避免当前示例中的视觉松散和不对齐问题。

## 技术实现说明

### HTML 结构调整

现有主 HTML 将从“编辑区 + 预览区”结构改成：

- 顶部工具栏
- 主编辑容器
- 单独的 `rules.html` 页面
- 隐藏的全屏预览弹层
- 隐藏的文件选择器
- toast 提示容器

### CSS 拆分

把当前页面内联样式迁移到 `styles/editor.css`，并分块维护：

- 全局基础样式
- 工具栏样式
- 主编辑区样式
- 规则页样式
- 预览弹层样式
- toast 样式
- 预览内容排版样式

### JS 拆分

把当前页面内联脚本迁移到 `scripts/editor.js`，拆成若干职责清晰的函数：

- 编辑区变更与渲染
- 打开规则页
- 规则加载与复制
- 打开文件
- 保存 Markdown
- 复制 HTML
- 预览弹层打开/关闭
- toast 提示

### 离线依赖

将 `marked` 本地化，避免任何 CDN 请求。

若后续希望彻底单文件化，可在下一版再考虑把本地 JS/CSS 回收进单一 HTML；本次不做，以保证结构可维护。

## 错误处理

### 规则文件读取失败

如果浏览器因为 `file://` 限制无法读取 `规则.txt`：

- `rules.html` 继续正常打开
- 规则区域回退到内置默认规则文本
- 通过轻提示告知“已使用内置规则”即可，不阻断操作

### 剪贴板失败

如果浏览器不允许直接写入剪贴板：

- 自动降级方案尝试复制
- 若仍失败，提示用户手动选择复制

### 文件打开失败

显示错误 toast，不清空当前编辑内容。

### 保存失败

浏览器端保存一般通过 Blob 下载实现，理论失败概率低；若异常发生，提示用户重试。

3. 点击工具栏 `规则` 能打开本地 `rules.html`

8. 点击 `复制 HTML` 后可复制渲染结果

10. 关闭按钮、遮罩点击、`Esc` 关闭逻辑正常

## 后续可扩展点

这些不在第一版内，但当前结构应为它们留出余地：

- 多套规则模板切换
- 规则文件导入/切换
- 示例稿模板区
- 常用片段插入
- 一键生成公众号排版 HTML
- 自动保存本地草稿

## 推荐执行策略

推荐按以下顺序实施：

第一步，拆出本地 `CSS`、`JS`、`marked.min.js`。  
第二步，重构主页面为编辑器优先布局，并加入规则页入口。  
第三步，新增 `rules.html`，加入规则说明、规则展示和复制功能。  
第四步，改造预览为全屏弹层。  
第五步，统一视觉样式并修正红框呈现。  
第六步，做离线验证和交互收尾。

## 结论

本次改造的本质不是再做一个通用 Markdown 编辑器，而是把现有页面收束成一个真正面向公众号排版流程的本地工作台。

主页面专注写素材，规则通过工具栏按钮进入单独页面，预览单独全屏打开，所有依赖都在本地。这样既符合当前使用习惯，也避免规则信息长期挤占编辑空间，同时为以后继续叠加规则模板、多稿件工作流和自动化能力打下基础。
